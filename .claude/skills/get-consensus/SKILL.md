# Get Consensus Scores from consensus.app

## Overview

Take the validation queries generated by `/check-claims` and look up each one on consensus.app using the browser. Consensus searches peer-reviewed literature and returns a verdict (Yes/No/Mixed) with supporting papers. Produces a report linking each claim back to its scientific evidence.

## Input

Default queries file: `data/outputs/queries.jsonl`

If that file does not exist, fall back to: `data/claim_queries.jsonl`

If the user provides a file path as an argument, use that instead.

Each line is a JSON object. See CLAUDE.md for the full schema. Fields:
- `claim_id` — links back to the original claim in `claims.jsonl`
- `query` — the natural-language search query
- `why_this_query` — explanation of why this query validates the claim
- `preferred_sources` — array of source types (e.g. `["systematic review", "meta-analysis"]`)

## Prerequisites

- The Claude in Chrome MCP must be available (browser must be open)
- consensus.app must be accessible (no VPN restrictions)
- You may need to be logged in to consensus.app for full results — if a login wall appears, stop and ask the user to log in

## Process

### Step 1: Read Queries

Read all queries from the JSONL file. Note the total count.

### Step 2: Open Browser Tab

Use `tabs_context_mcp` to get an available browser tab ID. You will reuse this same tab for all queries.

### Step 3: Search Each Query

For each query, do the following:

**a. Build the URL**

URL-encode the query string and navigate to:
```
https://consensus.app/results?q=<URL-encoded-query>
```

Use `navigate` with the tab ID.

**b. Check for login wall or CAPTCHA**

Use `get_page_text` to read the page. If the text contains login prompts, sign-in requests, or CAPTCHA challenges:
- Stop immediately
- Tell the user: "consensus.app is asking for login. Please log in and then tell me to continue."
- Wait for the user to confirm before proceeding

**c. Extract results**

Use `get_page_text` to get the full page text. Parse out:

- **Consensus verdict**: Look for "Yes", "No", "Possibly", "Likely", "Unlikely", or a percentage number near "Consensus" at the top of results
- **Result count**: Number of papers found (e.g., "12 papers")
- **Top papers**: For each paper listed, extract:
  - Title
  - Authors (first author + et al.)
  - Year
  - Journal name
  - Any conclusion snippet or highlighted finding shown

If the page is still loading or shows no results yet, use `read_page` with `filter: "interactive"` to check the state, then try `get_page_text` again.

**d. Handle no results**

If no papers are found, record `consensus_verdict: "Insufficient evidence"`, `result_count: 0`, and `top_papers: []`.

**e. Pace between queries**

After each query (except the last), wait briefly before the next navigation to avoid rate-limiting.

### Step 4: Write Outputs

#### JSONL Data File

Write to `data/outputs/consensus-results.jsonl`, one JSON object per line:

```json
{"claim_id":"clm_000001","query":"...","consensus_verdict":"Yes","consensus_pct":72,"result_count":12,"top_papers":[{"title":"...","authors":"Smith et al.","year":2021,"journal":"NEJM","conclusion_snippet":"..."}],"url":"https://consensus.app/results?q=..."}
```

Fields:
- `claim_id`: from the query record
- `query`: the search query used
- `consensus_verdict`: "Yes" | "No" | "Mixed" | "Possibly" | "Likely" | "Unlikely" | "Insufficient evidence"
- `consensus_pct`: integer percentage if shown, or null
- `result_count`: number of papers found
- `top_papers`: array of up to 5 papers
- `url`: the exact URL used

If results were only partial (some queries failed), still write what was retrieved and note which queries were skipped.

#### Markdown Report

Write to `data/outputs/consensus-results.md`:

```markdown
# Consensus Evidence Report

**Source queries**: [queries file path]
**Date retrieved**: [today's date]
**Queries searched**: N / M total

## Summary

- Strong support (Yes / ≥70%): X claims
- Mixed or uncertain: Y claims
- Contradicted (No / <30%): Z claims
- Insufficient evidence: W claims

## Results

### 1. [claim_id] — [short claim summary from query]

- **Query**: [query text]
- **Verdict**: Yes (72%)
- **Papers found**: 12
- **URL**: https://consensus.app/results?q=...

**Top Papers**:

1. *[Paper title]* — [Authors], [Year], [Journal]
   > "[conclusion snippet]"

2. ...

---
```

### Step 5: Print Summary

Print to the conversation:
- Total queries searched
- Breakdown by verdict (Yes / No / Mixed / Insufficient)
- The boldest claim (highest `boldness_rating` if available from claims) and its verdict
- Output file paths

## Notes

- consensus.app may require login for more than a few searches per session. Free tier typically allows ~10-20 searches.
- The consensus meter percentage is the key signal: ≥70% = strong support, 30-70% = mixed, ≤30% = contradicted.
- If a claim has no matching papers, that itself is informative — record it as "Insufficient evidence".
- Do not navigate away from results to individual paper pages — extract what's visible on the results page only.
